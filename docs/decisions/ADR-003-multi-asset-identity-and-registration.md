# ADR-003: 다중 자산 식별과 동적 등록 계약

- 상태: 채택
- 일자: 2026-09-27
- 범위: MFS UDP/Protobuf 계약과 C2 자산 관리

## 결정

1. 프로토콜 버전을 2로 올리고 모든 자산 관련 메시지 헤더에 64비트
   `asset_id`와 `session_id`를 포함한다.
2. `asset_id`는 역할과 무관하게 배포 단위에서 유일한 비영(0이 아닌) 값이다.
   운영 배포에서는 형상관리된 자산 ID를 사용하며 실행 중 다른 역할에 재사용하지
   않는다.
3. `session_id`는 프로세스 시작마다 새로 생성하는 비영 64비트 값이다. 실제 배포는
   암호학적으로 안전한 난수 생성기를 사용하고 충돌 시 재생성한다.
4. 자산 발신 메시지에서 두 ID는 발신 자산과 현재 프로세스 세션을 뜻한다. C2 발신
   명령에서는 목적 자산과 목적 세션을 뜻한다.
5. 자산은 `AssetRegistration`으로 역할, 명령 포트, capability, 버전, Pan/Tilt 한계,
   동시 작업 여부와 lease를 광고하고 정상 종료 시 `AssetUnregister`를 보낸다.
6. v1과의 하위 호환은 제공하지 않는다. v1 또는 식별자가 없는 패킷은 계약 검증에서
   `unsupported protocol_version` 또는 식별자 누락으로 거부한다.

## 충돌과 재사용

- `asset_id`는 실행 중 재발급하지 않는다. 장비 교체 시에도 동일 논리 자산이면 ID를
  유지할 수 있지만 역할 변경은 별도 형상 변경으로 관리한다.
- 동일 `asset_id`의 새로운 `session_id` 등록은 재시작으로 처리한다. 이전 세션의
  상태와 pending 명령은 이후 레지스트리 단계에서 종료·무효화한다.
- 64비트 session ID가 충돌하면 등록을 거부하거나 새 값을 생성한다. 0은 예약값이다.

## 보안 제한

현재 UDP 메시지는 암호학적으로 인증되지 않는다. IP, Endpoint, ID와 세션 검증은
오동작과 단순 재생을 제한하지만 위조 방지를 보장하지 않는다. 동적 등록은 신뢰된
격리망에서만 사용하며 실제 배포는 방화벽·VPN·DTLS 또는 메시지 인증을 추가해야 한다.
